# Stack

## О программе

Работу выполнил студент 1-го курса ФРКТ МФТИ Кушнир Алексей.

Данная программа представляет собой реализацию стека на основе динамического массива с возможностью подключения дополнительных режимов для отладки и обнаружения повреждений памяти.

Стек работает по принципу LIFO — последним добавленный элемент извлекается первым.

Основные операции cо стеком:

- stack_init() — инициализация стека;
- stack_push() — добавление элемента в стек;
- stack_pop()  — извлечение элемента из стека;
- stack_verify() — проверка корректности состояния стека;
- stack_dump() — вывод подробной информации о состоянии стека;
- stack_destroy() — разрушение стека

## Режимы работы

В программе предусмотрено три режима, которые можно включать и выключать с помощью директив препроцессора:

#define DEBUG_MODE
#define CANARY_MODE
#define HASH_MODE

Каждый режим может использоваться независимо от остальных.

### DEBUG_MODE

Режим #DEBUG_MODE предназначен для отладки программы.

При его включении:

- выполняется проверка состояния стека перед основными операциями;
- сохраняется информация о последнем добавленном элементе;
- сохраняется информация о последнем извлечённом элементе;
- запоминается строка, в которой была обнаружена ошибка;
- запоминается функция, в которой была обнаружена ошибка;
- при обнаружении ошибки вызывается stack_dump().

stack_dump() выводит подробную информацию о текущем состоянии стека.

Если DEBUG_MODE отключён, отладочная информация и дамп не используются.

### CANARY_MODE

Режим`CANARY_MODE предназначен для обнаружения выхода за границы массива.

При включении режима память имеет структуру:
LEFT_CANARY - DATA - RIGHT_CANARY

При проверке стека программа сравнивает текущие значения канареек с сохранёнными значениями. Если одна из канареек была изменена, считается, что произошло повреждение памяти.

Информация о повреждении выводится в stack_dump() при включённом DEBUG_MODE.

### HASH_MODE

Режим HASH_MODE предназначен для контроля целостности данных стека и самой структуры stack_info_t.

В программе используются два значения:

- long hash_data;
- hash_struct;

hash_data используется для проверки массива элементов стека.

hash_struct используется для проверки полей структуры stack_info_t.

После изменения состояния стека значения хэшей пересчитываются.

Если значения различаются, программа сообщает об изменении соответствующей области памяти.

Информация об ошибке выводится только при включённом DEBUG_MODE.

Используемая в проекте функция хэширования представляет собой простую контрольную сумму и предназначена для обнаружения случайного изменения данных, а не для криптографической защиты.

## Поля структуры 

real_data	    указатель на массив элементов стека
capacity	    объем массива
size	        текущее количество элементов
struct_error    текущий код ошибки

При включённом CANARY_MODE добавляются:

data_with_canaries	указатель на область памяти с канарейками
left_canary	        значение левой канарейки
right_canar         значение правой канарейки

При включённом HASH_MODE добавляются:

hash_struct	контрольная сумма структуры
hash_data	контрольная сумма массива

При включённом DEBUG_MODE добавляются:

last_popped_element	последний извлечённый элемент
last_pushed_element	последний добавленный элемент
str_code_failure	строка возникновения ошибки
func_failure	    функция, в которой произошла ошибка

## Возвращение ошибок программы

Основные ошибки:

0	SUCCESS_FINISH_FUNCTION	Операция выполнена успешно
1	INIT_ERROR_LACK_OF_MEMORY	Недостаточно памяти при инициализации
2	PUSH_ELEMENT_ERROR_LACK_OF_MEMORY	Недостаточно памяти при увеличении массива
3	POP_ELEMENT_ERROR_LACK_OF_MEMORY	Недостаточно памяти при уменьшении массива
4	ERROR_INCORRECT_CAPACITY	Некорректный объем стека
5	ERROR_NULL_DATA	Указатель на данные равен NULL
6	ERROR_SIZE_LESS_THAN_ZERO	Размер стека меньше нуля
7	ERROR_NULL_PTR_ON_STRUCT	Указатель на структуру равен NULL
8	ERROR_SIZE_MORE_THAN_CAPACITY	Размер больше вместимости
9	ERROR_SIZE_VALUE_NOT_POISONED	Неиспользуемая ячейка не содержит POISON
10	ERROR_POPED_ELEMENT_IS_POISONED	Последний извлечённый элемент имеет значение POISON
11	LEFT_CANARY_DISTRUCTED	Повреждена левая канарейка
12	RIGHT_CANARY_DISTRUCTED	Повреждена правая канарейка
13	HASHES_STRUCT_NOT_MATCH	Хэш структуры не совпадает
14	HASHES_DATA_NOT_MATCH	Хэш данных не совпадает
15	ERROR_STACK_IS_EMPTY_TO_POP	Попытка извлечь элемент из пустого стека

Ошибки, относящиеся к конкретным режимам, добавляются только при включении соответствующего режима.

## Функции программы

### stack_init()
Инициализирует стек и выделяет память под массив элементов.

В зависимости от включённых режимов также:

- создаёт область с канарейками;
- устанавливает начальные значения канареек;
- заполняет свободную часть массива POISON;
- вычисляет хэш данных;
- вычисляет хэш структуры.

## stack_push(stack_info_t* stack_info, TYPE_DATA_ELEMENTS push_element);

Добавляет элемент в стек.

Перед выполнением операции при включённом DEBUG_MODE выполняется проверка состояния стека.

Если массив заполнен, его вместимость увеличивается.

После добавления элемента обновляются контрольные значения хэшей.

## stack_pop(stack_info_t* stack_info, TYPE_DATA_ELEMENTS* pop_element);

Извлекает последний элемент из стека.

Перед извлечением выполняется проверка состояния стека.

После извлечения освободившаяся ячейка заполняется POISON.

При необходимости вместимость массива уменьшается.

После выполнения операции обновляются хэши.

## stack_verify(stack_info_t* stack_info);

Проверяет корректность состояния стека.

В зависимости от включённых режимов проверяются:

указатели;
size;
capacity;
наличие данных;
значения POISON;
левая канарейка;
правая канарейка;
хэш массива;
хэш структуры.

При обнаружении ошибки сохраняется информация о месте её возникновения.

### stack_dump(stack_info_t stack_info);

Функция доступна при включённом DEBUG_MODE.

Выводит подробную информацию о состоянии стека:

код ошибки;
строку возникновения ошибки;
функцию возникновения ошибки;
size;
capacity;
адреса выделенной памяти;
значения хэшей;
значения канареек;
последний добавленный элемент;
последний извлечённый элемент;
содержимое массива.

Использование stack_dump() позволяет быстро определить причину повреждения стека.

### stack_destroy(stack_info_t* stack_info);

Освобождает память, выделенную под стек, и очищает основные поля структуры.

### fill_the_array_poison(stack_info_t* stack_info);

Заполняет неиспользуемую часть массива значением POISON.

### check_empty_stack_for_pop(stack_info_t* stack_info);

Проверяет, является ли стек пустым перед выполнением stack_pop().

### hash_function_for_data(stack_info_t* stack_info);

Вычисляет контрольную сумму массива элементов стека.

### hash_function_for_struct(stack_info_t* stack_info);

Вычисляет контрольную сумму структуры stack_info_t.

Поля, используемые для хранения самих хэшей и диагностической информации, исключаются из расчёта.
